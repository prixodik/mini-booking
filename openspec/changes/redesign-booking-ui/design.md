# Design

## Context

Фронтенд: Nuxt 3 (SPA), PrimeVue 4.5.5, `@primeuix/themes` 3.1.1 (Aura, `darkModeSelector: false`), страница `pages/index.vue`, компоненты
`components/booking/{SlotList,DateFilter,BookingDialog}.vue`, `layouts/default.vue`. Имена классов уже близки к БЭМ (`slot__time`, `form__field`,
`layout__header`), но стили лежат в `scoped`-блоках без общих токенов, цвета захардкожены, вид — «стандартный».

## Goals / Non-Goals

**Goals:** аккуратная светлая тема; БЭМ с проверяемыми правилами; общие токены; адаптивность 360 / 768 / 1280; минимум нового кода и зависимостей.

**Non-Goals:** тёмная тема, новые функции, смена логики и API, анимации.

## Варианты визуальной основы

Выбор оставлен Alex. Проверенные факты отмечены источниками; непроверенное помечено «не проверено».

### A. Пресет PrimeVue 4 + кастомизация через `definePreset` (рекомендуется)

- Что это: берём встроенный пресет (Aura) и переопределяем токены: `semantic.primary`, поверхности, радиусы, при необходимости токены отдельных компонентов.
- Подтверждено документацией PrimeVue ([primevue.dev/theming/styled](https://primevue.dev/theming/styled), на него перенаправляет primevue.org; текст получен через Context7):
  доступны пресеты Aura, Material, Lara, Nora; `definePreset(base, tokens)` переопределяет токены при настройке; «primary» по умолчанию
  маппится на emerald; рекомендуется менять токены, а не стили компонентов классами; Lara основан на Bootstrap, Nora вдохновлён enterprise-приложениями, Material — Google Material v2.
- Плюсы: остаёмся в согласованном стеке (PrimeVue 4), минимум кода (один файл пресета + `tokens.css`), БЭМ сочетается естественно (внутренности — токены, раскладка — БЭМ-классы).
- Минусы: «готового шаблона страницы» нет — композицию (шапка, карточки слотов) пишем сами; дизайн зависит от аккуратности токенов.
- Трудоёмкость: низкая (≈ 1–2 часа с проверкой на 360 / 1280 px).
- Lara не берём: он «на основе Bootstrap», а исходная жалоба Alex — вид «как из Bootstrap».

### B. Шаблон Sakai-Vue (официальный, PrimeTek)

- Источник: [github.com/primefaces/sakai-vue](https://github.com/primefaces/sakai-vue).
- Проверено по репозиторию (GitHub API и `package.json` на 2026-11-16): лицензия MIT; 1134 звезды; не архивирован; последний push 2026-02-02;
  сборка Vite + `vue-router`; зависимости `primevue ^4.5.4`, `@primeuix/themes ^2.0.0`, Tailwind CSS 4 (`tailwindcss-primeui`), Sass; в `src/` — `layout/` (AppTopbar, AppSidebar, AppMenu, AppFooter), `views/`.
  Это админ-шаблон (боковое меню, верхняя панель, дашборд), а не шаблон одностраничного приложения.
- Плюсы: цельный визуальный язык PrimeTek, готовые topbar/layout.
- Минусы: это Vite-приложение, а не Nuxt (отдельного `sakai-nuxt` в организации `primefaces` на GitHub не найдено — запрос вернул 404); тянет Tailwind 4 и Sass,
  то есть второй способ стилизации рядом с БЭМ (утилитарные классы противоречат требованию БЭМ); для одной страницы избыточен.
  Совместимость с Nuxt 3 не проверялась (перенос потребовал бы переписывания layout и роутинга).
- Трудоёмкость: высокая; допустимо использовать только как визуальный ориентир и заимствовать токены/идеи, не код.

### C. Другая библиотека (Nuxt UI), только для сравнения

- Источник: [github.com/nuxt/ui](https://github.com/nuxt/ui) (MIT, 7084 звезды, активен), npm `@nuxt/ui` 4.12.2 (MIT, Node `^20.19.0 || >=22.12.0`, peer `tailwindcss ^4`, зависит от `@nuxt/kit ^4`).
- Плюсы: современный готовый вид, много компонентов.
- Минусы: смена библиотеки перекрывает уже согласованный стек (PrimeVue 4) и требует переписать диалог, `ConfirmDialog`, `Toast`, `SelectButton`; построена на Tailwind (конфликт с БЭМ-требованием);
  зависимость от `@nuxt/kit ^4` — совместимость с Nuxt 3 не проверена.
- Трудоёмкость: высокая. Не рекомендуется.

### Рекомендация

Вариант **A**: кастомный светлый пресет на базе Aura (`definePreset`) + БЭМ-композиция страницы + токены в `tokens.css`. Он решает исходную жалобу («стандартный вид») без смены стека и без второй системы стилизации.
Для визуального ориентира можно смотреть демо Sakai ([sakai.primevue.org](https://sakai.primevue.org)) (страница отвечает HTTP 200; содержимое демо не изучалось).

## Decisions

### БЭМ и размещение стилей

- Формат `block__element--modifier`, kebab-case, глубина — один уровень элемента.
- Стили в `<style scoped>` внутри `.vue` (а не в отдельных файлах): так делает Vue/Nuxt по умолчанию, стиль лежит рядом с разметкой (проще объяснять и править за 10–15 минут на защите),
  изоляция исключает утечки. Минус — стили PrimeVue-внутренностей не затрагиваются, но это и требуется (мы их меняем токенами).
- Классы на PrimeVue-компонентах попадают на их корневой элемент (наследование атрибутов Vue); для частей внутри компонента используется `pt`. Что именно попадает на корень у `Dialog` и `SelectButton` — не проверено, проверить при реализации.
- Глобально только `tokens.css` и `base.css` (`body`, `box-sizing`, `color-scheme: light`). Подключаются в `nuxt.config.js` → `css`.

Блоки (по компонентам):

```
layout            шапка и контейнер            layout__header, layout__title, layout__subtitle, layout__content
page              страница бронирования        page__filter, page__message, page__loading, page__empty, page__tz
date-filter       фильтр дат                   date-filter__item, date-filter__item--active
slot-list         список                       slot-list__item
slot-card         карточка слота               slot-card__time, slot-card__status, slot-card__action; --available | --booked | --past
booking-dialog    форма брони                  booking-dialog__slot, booking-dialog__form, booking-dialog__field, booking-dialog__error, booking-dialog__actions
```

(Если выбранное разбиение отличается от текущего — `SlotList.vue` делится на `SlotList` и `SlotCard`; решение принимается при реализации, имена блоков фиксируются в `tasks.md`.)

### Токены (`assets/css/tokens.css`, префикс `--mb-`)

```
--mb-color-bg            #F6F8FB   фон страницы
--mb-color-surface       #FFFFFF   карточки, диалог
--mb-color-text          #1F2937   основной текст
--mb-color-text-muted    #4B5563   вспомогательный текст
--mb-color-border        #D9E0EA   декоративные границы карточек
--mb-color-border-input  #748096   границы полей ввода
--mb-color-accent        #2F5BEA   акцент (кнопки, фокус, выбранная дата)
--mb-color-accent-hover  #2549C4
--mb-color-available-fg  #166534   --mb-color-available-bg #DCFCE7
--mb-color-booked-fg     #9A3412   --mb-color-booked-bg    #FFEDD5
--mb-color-past-fg       #4B5563   --mb-color-past-bg      #F3F4F6
--mb-color-danger        #B91C1C   --mb-color-danger-bg    #FEE2E2
--mb-space-1..6          4, 8, 12, 16, 24, 32 px
--mb-radius-sm|md|lg     6, 10, 16 px
--mb-font-family         'Inter', system-ui, ... (шрифт подключается, только если Alex согласует; иначе системный)
--mb-container-max       1120px

```

Пресет PrimeVue использует те же значения: `semantic.primary.500 = #2F5BEA` (белый текст на ней 5.52:1), `primary.600 = #2549C4` для hover. Полная шкала 50–950 генерируется при реализации
(как именно Aura маппит `primary.500/600` на кнопки в светлой теме — по документации не проверено, проверить визуально и по контрасту).

### Статусы не только цветом

`slot-card__status`: иконка + подпись + цвет — «Свободен» (`pi-check-circle`), «Занят» (`pi-lock`), «Прошёл» (`pi-clock`). У прошедших слотов дополнительно приглушённая карточка и нет кнопок действий.

### Адаптивность

- Mobile-first, базовая ширина 360 px; медиазапросы `min-width: 768px` и `min-width: 1280px`.
- Сетка слотов: `grid-template-columns: 1fr` → `repeat(2, 1fr)` (≥768) → `repeat(3, 1fr)` (≥1280); контейнер `max-width: var(--mb-container-max)`, отступы 16 px (телефон) / 24 px.
- Фильтр дат: сетка `repeat(auto-fit, minmax(76px, 1fr))` (7 дат на 360 px укладываются в 2 строки), высота кнопки ≥ 44 px, без горизонтального скролла.
- Шапка: на телефоне заголовок и подпись в колонку, на ≥768 px — в строку.
- Кнопки и поля формы на ≤767 px: `min-height: var(--mb-tap-min)`. Диалог — `width: min(26rem, 100vw - 32px)`; PrimeVue-диалог на телефоне настраивается свойством `breakpoints`/`pt`, не `.p-dialog` (не проверено, как именно в 4.5.5 — проверить при реализации).

### Проверяемость

Команды (запускаются из `frontend/`, зависимостей не требуют, должны возвращать пусто):

```bash
grep -rnE ":deep|>>>|/deep/|!important" components pages layouts
grep -rnE "^\s*(\.p-|#|[a-z]+\s*[{,])" components pages layouts --include=*.vue   # селекторы по .p-*, id и тегам внутри <style>
grep -rnE "#[0-9a-fA-F]{3,8}\b|rgb\(" components pages layouts --include=*.vue    # цветовые литералы
grep -rLn "scoped" components pages layouts --include=*.vue | xargs grep -ln "<style"   # <style> без scoped
```

Вторая команда приблизительна (может давать ложные срабатывания в `<script>`/`<template>`); уточняется при реализации (например, ограничение поиска блоками `<style>` через `awk`).
Строгая альтернатива: `stylelint` + `stylelint-selector-bem-pattern` (npm: `stylelint-selector-bem-pattern` 5.0.0, MIT, peer `stylelint ^17`; `stylelint` 17.x требует Node ≥ 20.19 — у Alex Node 22.22, подходит).
Работа плагина с `.vue` (нужен `postcss-html`) не проверена. Устанавливаем только по согласованию с Alex.

## Risks / Trade-offs

- **Лицензия `@primeuix/themes` 3.x.** Установлена версия 3.1.1; её `LICENSE.md` («PrimeUI License», PrimeTek) говорит о двух лицензиях: бесплатной Community
  (для организаций до 1 млн USD выручки, менее 5 разработчиков, менее 10 сотрудников, физических лиц, студентов и некоммерческих проектов — с ежегодным подтверждением права) и платной Commercial;
  также «a valid license key is required»: отсутствие ключа «may cause the software to display a license notice»; пакет распространяется скомпилированным.
  Версии `@primeuix/themes` 1.2.5, 2.0.0 и 2.0.3 имеют лицензию MIT (по npm); Sakai-Vue использует `@primeuix/themes ^2.0.0`. `primevue` 4.5.5 — MIT; его зависимость `@primeuix/styles ^2.0.3`.
  Что именно показывает 3.1.1 без ключа (видимое уведомление или нет) — **не проверено**; Alex ничего подобного пока не сообщал.
  Рекомендация: закрепить `@primeuix/themes` на MIT-линии `~2.0.3` (требует проверки совместимости с `primevue` 4.5.5: Sakai-Vue использует `primevue ^4.5.4` вместе с `@primeuix/themes ^2.0.0`, но на 4.5.5 не проверялось).
  Решение — за Alex; это отдельное изменение зависимостей и `package-lock.json`.
- Шрифт Inter (если подключать) — внешний ресурс; без согласования используем системный стек.
- Переименование блоков/классов может задеть тесты и скриншоты; логических тестов фронтенда нет, регресс проверяется вручную по `booking-ui`.
- Расчёт контраста относится к выбранным по умолчанию цветам; при смене акцента цифры меняются.

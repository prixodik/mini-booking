# Spec Delta

## Purpose
Описывает страницу бронирования: отображение слотов, фильтр по дате, формы и поведение при асинхронных запросах и ошибках.

## ADDED Requirements

### Requirement: Slot list with statuses
Страница SHALL показывать слоты выбранной даты: дату, время начала и окончания и статус. Свободные, занятые и прошедшие слоты MUST различаться как цветом, так и текстовой подписью (например «Свободен», «Занят», «Прошёл»).

#### Scenario: Различимые статусы
- **WHEN** загружены слоты с `available`, `booked` и `past`
- **THEN** у каждого слота видна своя подпись и стиль, а действия доступны только свободным (бронирование) и занятым будущим слотам (отмена)

### Requirement: Display in schedule timezone
Даты и время SHALL отображаться в часовом поясе расписания (`meta.timezone` из `GET /api/slots`), а не в поясе браузера.

#### Scenario: Браузер в другом поясе
- **WHEN** пояс браузера отличается от `meta.timezone`
- **THEN** слот 09:00 по времени расписания показывается как 09:00

### Requirement: Date filter
Страница SHALL один раз загружать расписание и фильтровать слоты по дате в браузере. Список дат MUST строиться из загруженных слотов в поясе расписания, по умолчанию выбирается сегодняшняя дата (в поясе расписания), а при её отсутствии — первая доступная.

#### Scenario: Смена даты
- **WHEN** пользователь выбирает другую дату
- **THEN** список показывает 9 слотов выбранного дня без нового запроса к API

### Requirement: Responsive layout
Страница MUST быть удобна на ноутбуке и телефоне: без горизонтальной прокрутки при ширине от 360 px, с достаточно крупными элементами управления.

#### Scenario: Узкий экран
- **WHEN** страница открыта при ширине 360 px
- **THEN** все слоты, статусы и кнопки действий доступны без горизонтальной прокрутки

### Requirement: Booking form
Для свободного слота SHALL открываться форма с полями «Имя» и «Email». Обязательность полей и формат email MUST проверяться в браузере до отправки.

#### Scenario: Пустая форма
- **WHEN** пользователь отправляет форму с пустыми полями
- **THEN** запрос не отправляется, под полями видны сообщения о необходимости заполнить их

### Requirement: Loading and blocked actions
Пока запрос выполняется, страница SHALL показывать индикатор загрузки и блокировать связанное действие (кнопки отправки, отмены и обновления), чтобы исключить повторную отправку.

#### Scenario: Двойной клик
- **WHEN** пользователь дважды быстро нажимает «Забронировать»
- **THEN** отправляется один запрос, кнопка отключена до ответа

### Requirement: Successful create and cancel refresh data
После успешного создания (201) или отмены (204) страница SHALL обновлять список без перезагрузки страницы и сообщать об успехе.

#### Scenario: Успешное бронирование
- **WHEN** сервер вернул 201
- **THEN** форма закрывается, слот отображается как занятый, показано уведомление

#### Scenario: Успешная отмена
- **WHEN** сервер вернул 204 на отмену
- **THEN** слот отображается как свободный

### Requirement: Validation errors (422)
При ответе 422 страница SHALL показать ошибки из `errors` под соответствующими полями формы, оставить форму открытой и сохранить введённые данные.

#### Scenario: Ошибка email с сервера
- **WHEN** сервер вернул 422 с `errors.customer_email`
- **THEN** сообщение отображается под полем Email

### Requirement: Conflict handling (409)
При ответе 409 страница SHALL показать сообщение сервера с причиной, закрыть форму и обновить список слотов.

#### Scenario: Слот занят другим пользователем
- **WHEN** сервер вернул 409 «Этот слот уже занят»
- **THEN** сообщение видно пользователю, а слот в списке отображается занятым

### Requirement: Network and server errors with retry
При сетевом сбое или ответе 5xx страница SHALL показывать сообщение об ошибке и предлагать «Повторить» то же действие (загрузку списка, создание или отмену), не теряя введённые данные формы.

#### Scenario: Сервер недоступен при загрузке
- **WHEN** загрузка списка слотов завершилась ошибкой сети
- **THEN** показано сообщение об ошибке с кнопкой «Повторить», повторный запрос запускается по нажатию

#### Scenario: Сбой при отправке формы
- **WHEN** отправка брони завершилась ошибкой 500
- **THEN** форма остаётся открытой с данными, видна ошибка и можно отправить снова

### Requirement: Cancel with confirmation
Для занятого будущего слота SHALL быть действие «Отменить бронь» с диалогом подтверждения. Если сервер отвечает 404 на отмену (бронь не найдена или уже отменена), страница MUST показать сообщение сервера и обновить список.

#### Scenario: Подтверждение
- **WHEN** пользователь нажимает «Отменить бронь» и подтверждает
- **THEN** отправляется `DELETE /api/bookings/{booking_id}`

#### Scenario: Отказ от отмены
- **WHEN** пользователь закрывает диалог без подтверждения
- **THEN** запрос не отправляется

### Requirement: API access isolated from components
Работа с HTTP SHALL быть вынесена в модуль `services/bookingApi.js`, а состояние и действия — в composable `composables/useBookingSlots.js`; компоненты MUST NOT вызывать `fetch` напрямую. Для состояния используется только реактивность Vue.

#### Scenario: Единая точка API
- **WHEN** в `components/`, `layouts/`, `pages/` и `app.vue` ищутся вызовы `fetch` или `axios`
- **THEN** их нет

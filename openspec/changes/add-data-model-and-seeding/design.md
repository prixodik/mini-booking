# Design

## Context

ТЗ оставляет структуру таблиц и способ хранения отмен на усмотрение автора. Гарантия уникальности должна опираться на БД; приложение должно быть переносимо между SQLite/MySQL/PostgreSQL.

## Goals / Non-Goals

**Goals:** простая схема; гарантия на уровне БД; сохранение истории отмен; детерминированное время.

**Non-Goals:** повторяющиеся брони, несколько комнат, пользователи.

## Decisions

### Схема

```
slots     id, starts_at (UNIQUE), ends_at, created_at, updated_at
bookings  id, slot_id (FK → slots.id), customer_name, customer_email,
          active_slot_id (NULL, UNIQUE), cancelled_at (NULL), created_at, updated_at
```

### Уникальность: `active_slot_id` + UNIQUE

- Активная бронь: `active_slot_id = slot_id`; отменённая: `NULL`. UNIQUE-индекс допускает много NULL (SQLite, MySQL, PostgreSQL), но запрещает две активные брони на один слот.
- **Рассмотрено и отклонено:**
  - *Частичный unique-индекс* `WHERE cancelled_at IS NULL` — поддерживается SQLite и PostgreSQL, но не MySQL; теряется переносимость.
  - *Физическое удаление при отмене* + `UNIQUE(slot_id)` — проще, но история отмен пропадает.
  - *`UNIQUE(slot_id, cancelled_at)`* — NULL не конфликтуют, поэтому не защищает.
  - *Проверка `exists()` перед вставкой / `lockForUpdate`* — гонка между проверкой и вставкой; в SQLite нет блокировок строк. Допустима только как дополнительная проверка для понятного сообщения, источник истины — индекс.
- Поле `active_slot_id` ведётся только кодом сервиса бронирования (создание/отмена); это зафиксировано в README.

### Время

- В БД — UTC; расписание строится в `config('app.timezone')` (`Europe/Moscow` в `.env.example`).
- Laravel по умолчанию пишет datetime как строку в часовом поясе приложения без указания пояса (проверить при реализации). Чтобы данные не зависели от `APP_TIMEZONE`, `starts_at`/`ends_at` пишутся и читаются через явный кастом/аксессор: запись `->utc()`, чтение `Carbon::parse($v, 'UTC')->setTimezone(config('app.timezone'))`. Формат одинаков, поэтому сравнение строк в SQLite корректно (проверить при реализации).
- «Сейчас» берётся из `now()` (Carbon), что позволяет фиксировать время в тестах через `Carbon::setTestNow`.

### Seeder

- Для `day = 0..6`: `today = now()->startOfDay()` в `app.timezone`, затем `day`-й день, для `hour = 9..17`: слот `[hour:00, hour+1:00)` в локальном времени, переводится в UTC.
- Идемпотентность: `Slot::upsert(rows, ['starts_at'], ['updated_at'])` или `insertOrIgnore` по unique `starts_at`; бронирования Seeder не трогает. Прошлые слоты сегодняшнего дня создаются как обычные.
- Параметры (9, 18, 60 мин, 7 дней) — в `config/booking.php`.

## Risks / Trade-offs

- Мягкая отмена добавляет поле `active_slot_id`, которое нужно держать согласованным; смягчается единственной точкой записи (сервис) и тестом.
- Кастом времени — небольшой дополнительный код ради независимости от `APP_TIMEZONE`.
- В SQLite нельзя показательно проверить настоящую параллельность; гарантия проверяется нарушением уникальности и документируется.

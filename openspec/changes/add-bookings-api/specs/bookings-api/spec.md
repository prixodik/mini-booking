# Spec Delta

## Purpose
Определяет контракт создания и отмены бронирований и поведение при ошибках и одновременных запросах.

## ADDED Requirements

### Requirement: Create booking
`POST /api/bookings` SHALL принимать `slot_id`, `customer_name`, `customer_email` и при успехе возвращать статус 201 и JSON `{"data": {"id": <ID брони>}}`.

#### Scenario: Успешное бронирование
- **WHEN** отправлены корректные данные для свободного будущего слота
- **THEN** ответ 201 содержит `data.id`, а в БД появляется одна активная бронь этого слота

### Requirement: Validation
Запрос MUST валидироваться средствами Laravel (FormRequest): `slot_id` обязателен, целое число и существует в `slots`; `customer_name` обязателен, строка, не длиннее 255 символов; `customer_email` обязателен, корректный email, не длиннее 255 символов. При ошибке SHALL возвращаться 422 и стандартный JSON Laravel `{"message": "...", "errors": {"<поле>": ["..."]}}`; бронь не создаётся.

#### Scenario: Пустые поля
- **WHEN** тело запроса пустое
- **THEN** ответ 422 содержит ошибки для `slot_id`, `customer_name` и `customer_email`

#### Scenario: Несуществующий slot_id
- **WHEN** `slot_id` равен 999999
- **THEN** ответ 422 содержит ошибку в `errors.slot_id`, а не 404 и не 409

#### Scenario: Некорректный email
- **WHEN** `customer_email` равен `not-an-email`
- **THEN** ответ 422 содержит ошибку в `errors.customer_email`

### Requirement: Occupied slot conflict
Если у слота уже есть активная бронь, API MUST вернуть 409 и JSON `{"message": "<понятное сообщение на русском>"}`; вторая активная бронь не создаётся.

#### Scenario: Повторный запрос на занятый слот
- **WHEN** на слот с активной бронью приходит ещё один корректный запрос
- **THEN** ответ 409 с сообщением «Этот слот уже занят», а активных броней слота остаётся одна

### Requirement: Past slot conflict
Если `starts_at` слота меньше или равен текущему серверному времени, API MUST вернуть 409 с сообщением «Этот слот уже прошёл» и не создавать бронь. Проверка прошедшего слота SHALL выполняться раньше проверки занятости.

#### Scenario: Бронь прошедшего слота
- **WHEN** запрошена бронь слота, который уже начался
- **THEN** ответ 409 с сообщением о прошедшем слоте, бронь не создана

### Requirement: Concurrent requests create exactly one booking
При одновременных запросах на один свободный слот система SHALL создать ровно одну активную бронь; остальные запросы MUST получить 409. Гарантия MUST опираться на UNIQUE-индекс БД: нарушение уникальности при вставке перехватывается и превращается в 409, а предварительная проверка не считается достаточной.

#### Scenario: Гонка двух запросов
- **WHEN** два запроса на один свободный слот проходят предварительную проверку одновременно
- **THEN** вставка одного из них нарушает уникальный индекс, он получает 409, а активная бронь слота ровно одна

### Requirement: Cancel booking
`DELETE /api/bookings/{id}` SHALL отменять бронь, возвращая 204 без тела. Для неизвестного ID API MUST вернуть 404 JSON. Повторная отмена уже отменённой брони SHALL возвращать 204 (идемпотентно). Авторизация не требуется.

#### Scenario: Успешная отмена
- **WHEN** отменяется активная бронь будущего слота
- **THEN** ответ 204, а слот в `GET /api/slots` снова имеет `status = available`

#### Scenario: Повторная отмена
- **WHEN** DELETE вызывается второй раз для той же брони
- **THEN** ответ 204 и данные не меняются

#### Scenario: Неизвестный ID
- **WHEN** DELETE вызывается для несуществующего ID
- **THEN** ответ 404 в JSON

### Requirement: Rebooking after cancellation
После отмены будущий слот SHALL снова быть доступен для нового бронирования.

#### Scenario: Новая бронь после отмены
- **WHEN** бронь слота отменена и другой клиент бронирует тот же слот
- **THEN** ответ 201, а у слота снова одна активная бронь

### Requirement: Atomic creation
Создание брони MUST выполняться атомарно (одна транзакция/один INSERT), а любое непредвиденное нарушение целостности, кроме уникальности активной брони, не должно маскироваться под 409.

#### Scenario: Прочие ошибки БД
- **WHEN** при создании брони возникает непредвиденная ошибка БД
- **THEN** ответ 500 в JSON, а не 409

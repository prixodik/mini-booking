# Design

## Context

`httpClient.request` вызывает `fetch` без `signal`; любая ошибка `fetch` превращается в `ApiError({ status: 0 })`
«Нет связи с сервером…». `useBookingSlots.run` возвращает `{ status: 'error' }` для таких ошибок, страница показывает «Повторить».
`run` перезагружает список только при успехе, 409 и 404.

## Decisions

1. `httpClient.js`:
   ```js
   const TIMEOUT_MS = 15000 // запрос, не получивший ответа за 15 с, считается сбоем сети

   response = await fetch(url, { ..., signal: AbortSignal.timeout(TIMEOUT_MS) })
   } catch (error) {
     const timedOut = error?.name === 'TimeoutError'
     throw new ApiError({
       status: 0,
       timedOut,
       message: timedOut
         ? 'Сервер не ответил вовремя. Повторите попытку.'
         : 'Нет связи с сервером. Проверьте подключение и повторите попытку.',
     })
   }
   ```
   `ApiError` получает поле `timedOut` и геттер `isTimeout`. `isNetwork` (`status === 0`) остаётся верным и для таймаута,
   поэтому вся существующая обработка «Повторить» работает без изменений.
   Таймаут охватывает и чтение тела: `AbortSignal.timeout` прерывает `response.json()` с той же ошибкой `TimeoutError`.
   Сейчас ошибка чтения тела глушится (`data = null`), и при `response.ok` вызывающий код получил бы `null`. Поэтому в `catch`
   чтения тела таймаут пробрасывается той же `ApiError` (`timedOut: true`), а прочие ошибки разбора, как и раньше, дают `data = null`.
   Создание ошибки таймаута выносится в маленькую функцию `timeoutError()`, чтобы не дублировать её в двух `catch`.
2. `useBookingSlots.run`: в ветке ошибки — `if (error.isTimeout) await load({ silent: true })` перед `return { status: 'error' }`.
   Только для таймаута: при «нет связи» перезагрузка тоже упала бы и показала вторую ошибку.
3. 15 секунд: локальный `php artisan serve` отвечает за миллисекунды; на медленной мобильной сети запрос укладывается в несколько
   секунд; 15 с — запас, при котором пользователь ещё не бросает страницу. Константа в одном месте.

`AbortSignal.timeout` поддерживается всеми актуальными браузерами (Chrome 103+, Firefox 100+, Safari 16+).

Рассмотрено: `AbortController` + `setTimeout` с `clearTimeout` — то же самое в 5 строк вместо одной; нужно только для очень старых браузеров.

## Risks / Trade-offs

- Повтор после таймаута POST может получить 409, если первая бронь всё же создалась (сценарий «Бронь создалась, но ответ не дошёл»).
  Перезагрузка списка показывает это до повтора; идемпотентный ключ запроса — вне объёма.

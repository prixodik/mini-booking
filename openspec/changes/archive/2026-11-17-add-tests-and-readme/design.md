# Design

## Context

ТЗ требует ровно два теста и описание в README. Оценивается воспроизводимость запуска и умение объяснить решение.

## Goals / Non-Goals

**Goals:** стабильные тесты без привязки ко времени суток; README, по которому всё запускается с первого раза.

**Non-Goals:** покрытие 100%, тесты фронтенда, CI.

## Decisions

- **PHPUnit** (стандарт Laravel). `phpunit.xml`: `DB_CONNECTION=sqlite`, `DB_DATABASE=:memory:`, `APP_TIMEZONE` как в `.env.example`.
- **Фиксация времени:** в `setUp` — `Carbon::setTestNow(Carbon::parse('2026-01-05 08:00', config('app.timezone')))`, затем `SlotSeeder` (или фабрика слотов): в 08:00 все 9 слотов дня будущие, поэтому свободный будущий слот есть всегда. Дата в тесте выбрана произвольной, но неизменной.
- **Тест 1:** `postJson('/api/bookings', [...])` → `assertCreated()`, `assertJsonStructure(['data' => ['id']])`, `assertDatabaseCount('bookings', 1)`, проверка `active_slot_id`.
- **Тест 2:** первая бронь создаётся напрямую (сервис/фабрика), второй запрос через API → `assertStatus(409)`, `Booking::where('slot_id', ...)->whereNull('cancelled_at')->count() === 1`.
- **Параллельность** в PHPUnit на SQLite in-memory не проверить (один процесс, одно соединение); README честно говорит, что гарантию даёт UNIQUE-индекс, а тест проверяет её через последовательный повтор.
- **README** — на русском; структура: требования, установка, настройка `.env`, запуск, тесты, API (кратко), уникальность, время, допущения и незавершённое, процесс OpenSpec.

## Risks / Trade-offs

- Строго два обязательных теста означают меньший охват; дополнительные тесты опциональны и добавляются по остатку времени.
- Фиксированная дата в тестах должна быть в пределах окна Seeder относительно замороженного «сейчас» — иначе слотов не будет; поэтому Seeder запускается уже после `setTestNow`.

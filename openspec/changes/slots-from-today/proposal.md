# Proposal

## Why

Ревью (`review-mini-booking.md`, Ж-2): `GET /api/slots` отдаёт все слоты из БД. Seeder при каждом запуске в новый день добавляет
дни, а старые не удаляются, поэтому через месяц ответ и фильтр дат на странице содержат 30+ прошедших дней, которые никому не нужны.
ТЗ, п. 2–3 требует показывать слоты текущего дня, включая уже прошедшие, но не требует истории за прошлые дни. Alex попросил исправить.

## What Changes

- `GET /api/slots` возвращает слоты, начинающиеся не раньше 00:00 сегодняшнего дня в часовом поясе расписания (`app.timezone`).
  Прошедшие слоты сегодняшнего дня по-прежнему возвращаются со статусом `past`. Слоты прошлых дней и брони на них остаются в БД.
- Локальный scope `Slot::startingFrom($moment)`: переводит момент в UTC через `Slot::toDbValue()` и сравнивает с `starts_at`
  (единое место для запросов по времени слота).
- Тест: после запусков Seeder в два разных дня API отдаёт только слоты с сегодняшнего дня.
- README: строка про объём `GET /api/slots` в разделах «API» и «Допущения».

Вне объёма: удаление старых слотов, пагинация, параметры запроса (`?date=`), остальные пункты ревью (в т. ч. отложенный И-5 —
общий разговор о UTC в запросах; этот change лишь использует уже существующий `toDbValue`).

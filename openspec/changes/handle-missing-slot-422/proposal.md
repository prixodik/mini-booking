# Proposal

## Why

Ревью (`review-mini-booking.md`, Ж-7): если `POST /api/bookings` вернул 422 с ошибкой `errors.slot_id` (слот не существует),
`pages/index.vue` пишет её в общую ошибку диалога, а `BookingDialog.vue` при общей ошибке меняет кнопку на «Повторить». Повтор с
тем же несуществующим слотом снова получит 422: пользователь застревает в диалоге. Ошибка `slot_id` — не ошибка ввода (такого поля
в форме нет), а признак устаревшего списка, как 409. ТЗ, п. 4: «Покажите ошибки полей при 422, объясните причину конфликта при 409
и обновите список после конфликта». Alex попросил исправить.

## What Changes

- 422 с `errors.slot_id` обрабатывается как конфликт: диалог закрывается, показывается предупреждение с сообщением сервера
  («Выбранный слот не существует.»), список слотов перезагружается.
- 422 только с ошибками полей формы (`customer_name`, `customer_email`) — как сейчас: ошибки под полями, форма открыта, кнопка
  «Забронировать» (не «Повторить»).
- «Повторить» в диалоге остаётся только для сбоев сети и сервера.

Вне объёма: изменения API (код ответа 422 для несуществующего `slot_id` задан ТЗ), остальные пункты ревью.

# Proposal

## Why

Ревью (`review-mini-booking.md`, Ж-10): ТЗ, п. 3 разрешает отмену «по известному ID без авторизации», а `GET /api/slots` по ТЗ
отдаёт `booking_id`. Вместе с последовательными ID это значит, что любой посетитель может отменить любую бронь. Кроме того, у
`POST /api/bookings` нет ограничения частоты запросов: один клиент может занять все слоты. Для демо это допустимо, но README
сейчас упоминает только «отмена без авторизации» и не показывает, что автор видит риск и знает, как его закрыть. ТЗ, п. 5: в README
кратко описать решения и незавершённое. Alex: отметить в README.

## What Changes

- README, раздел «Допущения и что не сделано»: пункт «Безопасность демо» — два риска (отмена чужой брони, нет rate limit) и как их
  закрыть в реальном проекте (токен отмены в ответе на создание или UUID вместо последовательного ID, авторизация; `throttle` на POST).

Вне объёма: реализация защиты (ТЗ п. 1 выносит авторизацию за рамки), изменения кода.
